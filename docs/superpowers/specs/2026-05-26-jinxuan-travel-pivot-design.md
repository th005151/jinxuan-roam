# 金萱在路上 — Travel Blog Pivot Design

**Date**: 2026-05-26
**Status**: Spec draft, pending user review
**Predecessor**: [`2026-05-15-littlefoxmoney-redesign-design.md`](2026-05-15-littlefoxmoney-redesign-design.md)

## 0. Goal & Constraints

Pivot the existing `littlefoxmoney` Next.js codebase (a crypto-affiliate site, engineering 100% complete but never deployed) into a personal travel blog called **「金萱在路上」**, with content written and edited on a phone via Notion, syncing to the live site through a build-time pipeline. Ship to Vercel today.

**Hard constraints**:

- **No SEO redesign** — reuse all existing metadata / sitemap / JSON-LD / robots / OG infrastructure.
- **Mobile-first authoring** — every editing action must be doable on phone (Notion app + Vercel app).
- **Reuse existing shell** — keep the Next.js 15 + Tailwind 4 + MDX pipeline, ArticleHeader / TOC / sidebar / Footer / Privacy / About skeletons. Only swap branding text and the content layer.
- **Free tier only** — no paid services (Notion free, Vercel free, no Cloudinary).
- **Keep affiliate machinery** — generalize `exchanges` → `partners` so future Klook / Trip.com / KKday / Agoda / Booking / Expedia links plug in.

**Non-goals (explicitly out of scope for this pivot)**:

- Custom domain (use `*.vercel.app` first; swap later).
- Notion → site full automation (P2 follow-up using make.com).
- Multi-language (zh-TW only).
- Visual redesign beyond text / color stays on existing emerald palette.
- Image CDN / optimization beyond Next/Image defaults.

## 1. Architecture

### 1.1 Content pipeline

```
Notion Database「文章」
  │ (writer edits on phone)
  │
  ▼  build trigger (Vercel Redeploy from app, or Notion button → webhook)
scripts/sync-notion.mjs            (runs before `next build`)
  ├─ list pages where Status = Published
  ├─ for each page:
  │    ├─ fetch properties → frontmatter YAML
  │    ├─ fetch page blocks → notion-to-md → markdown body
  │    ├─ download cover + inline images → public/uploads/notion/<slug>/
  │    └─ rewrite image URLs to /uploads/notion/<slug>/<hash>.<ext>
  └─ write content/articles/<slug>.mdx
  │
  ▼
next build (existing @next/mdx pipeline, unchanged)
  ├─ ArticleHeader / TOC / Sidebar render unchanged
  ├─ sitemap.xml regenerated by next-sitemap
  └─ /[slug] static routes generated
  │
  ▼
Vercel deploy → live in ~30s
```

### 1.2 Notion Database schema

A single Notion database named **「文章」**. Page body holds the article body (Notion blocks: headings, paragraphs, lists, quotes, callouts, images, embeds — all converted to markdown by `notion-to-md`).

**Core properties**:

| Property      | Type                   | Purpose                                                      |
| ------------- | ---------------------- | ------------------------------------------------------------ |
| `Title`       | Title                  | Article title (also page name)                               |
| `Slug`        | Text                   | URL slug; empty → auto-derived from title (kebab-case)       |
| `Status`      | Select: Draft / Published | Only `Published` is synced                                |
| `Published At`| Date                   | Sort order + `<time datetime>` in metadata                   |
| `Excerpt`     | Text (multi-line)      | Meta description + article card subtitle                    |
| `Cover`       | Files (1)              | Article cover, OG image fallback                            |

**Travel-specific properties**:

| Property      | Type                                              | Purpose                                       |
| ------------- | ------------------------------------------------- | --------------------------------------------- |
| `Country`     | Select (日本 / 台灣 / 泰國 / 越南 / 韓國 / ...)     | "Browse by country" (M2 nav, schema ready now)|
| `Location`    | Text                                              | Specific spot (東京・嵐山 / 花蓮・玉里)        |
| `Trip Type`   | Select (背包客 / 自由行 / 親子 / 美食 / 露營 / 跟團)| Article taxonomy                              |
| `Travel Date` | Date                                              | Actual trip date (≠ Published At)             |
| `Tags`        | Multi-select                                      | Free-form tags (櫻花季 / 平價 / 小眾景點)      |

**Partner / affiliate properties**:

| Property        | Type                                                      | Purpose                                |
| --------------- | --------------------------------------------------------- | -------------------------------------- |
| `Partner`       | Select (klook / trip / kkday / agoda / booking / expedia / none) | Drives sidebar CTA; `none` hides it |
| `Partner Link`  | URL                                                       | Article-specific affiliate URL         |

**Derived (not stored in Notion)**:

- `readingTime` — computed at sync time from markdown body length (Chinese ≈ 350 chars/min).
- Word count, internal link analysis, etc. — done by sync script if useful.

## 2. Sync script behavior (`scripts/sync-notion.mjs`)

### 2.1 Inputs

- `NOTION_TOKEN` — internal integration token, scoped to the「文章」DB.
- `NOTION_DATABASE_ID` — UUID of the database.

### 2.2 Flow

1. Query DB filtered by `Status = Published`, sorted by `Published At` desc.
2. For each page:
   a. Read properties → build typed frontmatter object (validated by zod, fails loudly if a required field is missing).
   b. Derive `slug` if empty (kebab-case of title; if collision, append `-2`, `-3`...).
   c. Fetch page block children recursively (Notion API paginated).
   d. Convert blocks → markdown via `notion-to-md`, configured to:
      - Convert callouts to markdown block quotes (`>`); no new MDX component needed.
      - Convert images: capture URL, download to `public/uploads/notion/<slug>/<sha256-8>.<ext>`, rewrite to local path.
      - Convert embeds (YouTube, Twitter, Instagram): emit as markdown link with the source URL; richer embed components are P2.
   e. Compute `readingTime` (chars / 350, round up).
   f. Write `content/articles/<slug>.mdx` with YAML frontmatter + markdown body.
3. After all pages processed, write `content/articles/_index.json` (slug list + timestamps) for the next-sitemap step to enumerate.
4. Delete orphaned files in `content/articles/` (any `<slug>.mdx` not in current DB and not `*_seed.mdx`) so unpublishing in Notion removes the page.

### 2.3 Failure modes

- Notion API down → script exits with code 0 (do NOT fail the build), logs warning, leaves existing `content/articles/` in place. Site rebuilds with last-known content + seed.
- Required field missing on a page → script logs which page, **skips that page**, continues with others. Build still succeeds.
- Image download failure → keep original Notion URL (will 404 after 1 hour but doesn't break build). Log warning.
- Slug collision → suffix with `-2`, `-3`...

### 2.4 Performance budget

- Free Notion API: 3 req/sec rate limit; for <50 articles this is fine.
- Image downloads done in parallel with concurrency 4.
- Sync target: < 30 seconds for 20 articles.

## 3. Mobile workflow

**Basic version (ship today)**:

1. Notion app → 「文章」DB → New entry → write article in page body, fill properties.
2. When ready, change `Status` to `Published`.
3. Switch to Vercel app → project → Deployments → tap Redeploy on latest commit. Or trigger a manual deploy from the dashboard.
4. ~30s later, article is live.

## 4. Launch sequence

This is the spec's contract for "today". Concrete tasks belong in the implementation plan (next step), but the high-level sequence is:

1. **Branch hygiene & memory checkpoint** — commit anything pending, snapshot existing crypto state in case of rollback.
2. **Remove crypto content** — delete the 4 MDX files; strip crypto copy from `/about`, `/disclosure`, `/faq`, homepage; remove crypto-specific tests.
3. **Rebrand text** — siteConfig name/url/description, wordmark text, UTM source, metadata, JSON-LD author, OG image text.
4. **Generalize partner system** — rename `exchanges` → `partners`, refactor frontmatter field name, refactor 4 affiliate components' copy to travel context (no structural change).
5. **Notion sync infrastructure** — install `@notionhq/client` and `notion-to-md`, write `lib/notion.ts`, write `scripts/sync-notion.mjs`, wire `package.json` build script.
6. **Seed file** — author `_hello-jinxuan_seed.mdx` so build works before Notion DB exists.
7. **Verify locally** — `npm run build` succeeds with seed-only; `npm run dev` shows correct branding; existing 11/11 Playwright tests pass (after assertion rewrites).
8. **Provision Notion DB** — user creates database with the schema above, shares it to the internal integration.
9. **Sync test** — user adds 1–2 seed articles in Notion; `npm run sync` locally produces expected MDX; site renders correctly.
10. **Deploy to Vercel** — connect repo, set env vars, deploy. Site live at `*.vercel.app`.
11. **Smoke check on phone** — write a new article on Notion mobile, switch to Vercel app, redeploy, confirm live update.

## 6. Risks & mitigations

| Risk                                                                       | Mitigation                                                              |
| -------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Notion image URLs expire (1 hr) → broken images on build                   | Sync script downloads + rehosts to `public/uploads/notion/`             |
| User's first Notion DB schema doesn't match script's expectations          | Sync script logs missing fields per page; skips broken pages, continues |
| Vercel build minutes runs out from image downloads                         | Free tier 6000 build-min/month; image dl is one-time per image (cached by `next build` itself); will not approach limit at personal-blog scale |
| `content/articles/` getting overwritten loses git history                  | Files are .gitignored; canonical source is Notion. Seed file is exception |
| Old crypto site SEO baggage (not deployed) | None — `git log` will show history, but no crawlers indexed the dead branch |
| Site is "live but empty" until first Notion article is published           | `_hello-jinxuan_seed.mdx` provides one welcome article so site is not blank |
